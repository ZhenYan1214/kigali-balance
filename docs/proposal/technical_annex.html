Kigali Balance: Technical Annex

IEEE ClimateChain Global Hackathon 2026 · Track 3: Sustainable Supply Chains (also Track 1: Carbon Markets & Emissions Transparency) · Repository: github.com/ZhenYan1214/kigali-balance · All figures as of 2026-10-17

At a glance.
  • Problem: a kilogram sold as “reclaimed” or credited as “destroyed” is checked only inside the system that records it. No registry publishes which container, and how many kilograms, each of the 42.4 million destruction credits we audited draws on.
  • Design: one conservation rule (A.1), enforced on chain when each record is written. Every step that earns money needs a second, accountable signer (A.4–A.5).
  • Evidence: 162 unit tests, including a regression test for each fixed finding of two rounds of outside security review (each round found a High-severity laundering path; both are fixed; B.3); 10 fuzzed invariants; 7,359 of 7,359 simulated events replayed identically against the contracts; Slither reports no Medium or High finding.
  • Impact: for a market the size of Japan's, a median 0.06 MtCO₂e a year attributable to verification (5th–95th percentile 0.01–0.18), counting only gas that is destroyed (C).
  • Limits: market data is simulated; amounts are not yet confidential; collusion is bounded, not prevented (F).

Sections follow the IEEE call: architecture and specification (A), security and data-integrity assessment (B), climate impact (C), adoption and roadmap (D), testing (E). The problem statement is pages 1–2. Every number comes from a script in the repository. A clean GitHub-hosted Linux machine rebuilds every generated file on every push and fails if any of them changes by one byte; python scripts/rebuild.py --full reproduces this locally.

A. Architecture and technical specification

A.1 What the system is for, in one rule

Every kilogram claimed as “reclaimed” or “destroyed” must trace back to a kilogram recovered from a real, registered piece of equipment.

Kigali Balance is a reconciliation layer between the systems that already record HFC kilograms. We audited 436 public ODS (ozone-depleting substance) and HFC destruction and reclamation projects at ACR, CAR and Verra:

  • Certificate-of-destruction identifiers are public for 31% of the 42.4 million destruction credits, in three incompatible forms.
  • 58% have none. Most of these are California and Washington compliance credits, whose issuance does reconcile with the registries period by period.
  • 11% we did not assess.
No registry publishes which container and how many kilograms a credit draws on, so uniqueness at the kilogram level cannot be checked from outside. Almost all of these credits are for ODS destruction; HFC destruction crediting is only now opening (C, D). A shared ledger is used only because no single trusted operator spans all the parties (problem statement, §7).

A.3 Data model

  • Lot (UTXO-like): gas, integer grams, provenance class, tier, holder, origin unit, parent lots, cylinder ID. One open lot per physical cylinder at a time.
  • Provenance classes, which can never be swapped:
    • VIRGIN: minted against a quota document.
    • RECOVERED: from a registered unit.
    • RECLAIMED: made only from recovered lots.
    • UNKNOWN: legacy stock. Only the quota authority can register it. It is never reclaimed or credited, even after being charged into equipment: the lot that holds it when it comes back out stays marked through every later charge, recovery and split.
  • Equipment tiers.
    • A: in a national register (e.g. units ≥ 5 tCO₂e, which EU 2024/573 requires to be leak-checked).
    • B: small units registered at decommissioning from a nameplate photo (one photo, one unit) and a model database.
    • C is assigned at recovery, to: grams charged through the ledger in the previous 180 days; everything, if the unit was installed less than 180 days ago; and any undocumented gas charged into the unit. Tier C can never be reclaimed or credited.
  • Booked content per unit: starts at one charge, drawn down by each recovery, refilled only by recorded top-ups, never above one charge.
  • Destruction event: destroyed grams, destruction and removal efficiency (DRE), credit eligibility, and the weakest input tier. Each event can be claimed by one registry, once.

In ISO 22095:2020 chain-of-custody terms, this is the segregated model, not mass balance. Reclamation may blend recovered lots with each other, but virgin or unknown gas can never be mixed in. A mass-balance model would let a reclaimer sell “reclaimed” kilograms against an average, which is exactly the loophole the system closes. This positioning is based on published summaries of the standard [6].

A.5 Attestations

All off-chain evidence enters as EIP-712 typed data signed with secp256k1 and verified in the contract (Attestations.sol).

  • The domain binds chain ID and contract address.
  • High-s signatures are rejected.
  • Every attestation carries a nonce (no replay), is valid for 7 days, and can never be dated in the future.
  • Each device key is bound to one operator, and an operator can only use its own scale.
  • “Independent” is checked at the level of addresses: governance must vet that two addresses are not one entity.

A.6 AI modules

The modules read only what a regulator could observe: ledger events, the equipment register, the actor list and invoices. The simulator's ground truth is used only to score them; a test parses the source code to prove that no module opens it.

  • Each flag carries readable reasons, the model hash and a hash of its input snapshot.
  • Signals combine by noisy-OR, and a score ≥ 0.6 sends the case to a human.
  • The differential test writes every flag to FlagRegistry and reads it back. It recomputes the input hash independently from the replayed files. Only a regulator can close a flag.
  • Thresholds were fixed on development seeds. Each module was then scored on 20 simulated runs it had never seen, and on new ones whenever a version changed.

How to read these numbers.

  • They measure our own fraud generator. Naive fraud is detectable by construction: it buys gas on invoices the ledger never sees. Adaptive fraud is defined as staying inside each detector's honest range, and its volume is a simulator parameter. So “adapting forces fraudsters to stay small” (4 kg against 136 kg for ghost recoveries; 15 kg against 1,131 kg for distributors; only 14 kg against 28 kg for yield-inflating reclaimers) is a consistency check, not a discovery.
  • Precision depends on how much fraud the sample holds. If 1 company in 100 cheated, module A's precision would fall to about 0.5. The samples are small: the 95% interval on module C's 35% is 15–59%.
  • Module C's 35% is reached in year 3; at 12 months it is 5%.
  • The colluding co-signer is caught partly because it also serves a naive partner.
  • End-of-life closure. A fourth check lists registered units that left service with no recovery on the ledger. Its true unaccounted mass fell inside the IPCC-based estimate in 10 of 10 runs, but near the top of the range, because the simulator keeps small leak-checked units fuller than IPCC typical values.

  • L2 gas price about 0.001 gwei;

B. Security and data-integrity assessment

B.1 Scope, assets and trust assumptions

Assets.

  1. The integrity of each lot's provenance class: the “reclaimed” premium and carbon credits depend on it.
  2. The uniqueness of each destruction claim.
  3. Mass conservation per gas.
  4. The confidentiality of participants' commercial volumes.
  5. Long-term verifiability of the records.

What the ledger does not assume: that any single participant is honest, or that any submitted data is true.

What it does assume:

  • At least one independent counterparty in each money-making step is honest: the receiver weighs on its own scale, the owner co-signs, and the lab and the destruction verifier are independent.
  • Governance vets identities, so that two addresses are not one entity.
  • No single bloc controls governance (3 of 4 seats: regulator, registries, industry association, civil society).

Adversaries:

  • a reclaimer selling virgin or smuggled gas as reclaimed (reclaimed R-404A sold at a 40% premium over virgin in Q1 2025 [2]);
  • a service company or take-back point inventing recoveries;
  • a destruction facility overstating destruction;
  • a project developer seeking credits from two registries;
  • a competitor trying to disrupt another's business;
  • an outsider holding a stolen key.

B.4 How much can colluding parties still launder?

Rules cannot stop two parties who agree to lie, so we measured how much room they leave. In the model, every registered unit in the simulated market (the October 16 simulator population, 1,856 units) is padded to the limit by a colluding technician and owner, with the charge really left in each unit drawn from the IPCC 2006 Table 7.9 end-of-life ranges. The rules would then accept as “recovered”:

  • 323.5 kt CO₂e of virgin gas under a plain lifetime cap (375% of honest recovered volume);
  • 38.6 kt CO₂e under the booked-content rule we implemented (45%);
  • 30.0 kt CO₂e with an uncalibrated padding detector on top (35%).

Against a lifetime cap, the simplest rule a ledger could enforce, booked content removes 88% of the room. On a ledger only three years old, which has recorded few top-ups, it removes 57% (90.5 → 38.6 kt). A careful paper audit with a unit register would also apply roughly “one charge per unit”, so the gain over today's best practice is smaller. The gain is that the rule is enforced on every record, across organisations.

The rest cannot be closed by rules. Many honest units reach end of life far from full, so padding one to a full charge looks like an ordinary recovery. Off-ledger charging (T13) needs no false signature at all. That residue belongs to statistics and inspection.

B.5 Confidentiality

Today, lot grams and holders are ledger state that every consortium member can read. That is acceptable for a regulator but not for competing reclaimers.

The production path follows crypto exchanges' proof of reserves, which already proves that totals add up without revealing balances. Commitments (Pedersen) replace plain grams, and the contract checks conservation homomorphically: the sum of input commitments equals the sum of outputs plus losses. Range proofs are mandatory (e.g. Bulletproofs): without them a negative hidden amount could create mass, the known weakness of commitment-only reserve proofs [9]. Regulators would hold viewing keys.

We have not built this; it is roadmap stage 2.

B.6 Post-quantum migration path

Every signature in the system is secp256k1 ECDSA, which a large quantum computer would break.

  • What survives: records already on chain stay verifiable as history, as long as the chain's own history cannot be rewritten. That needs the chain's consensus signatures migrated too, which is the chain's job, not this application's.
  • What breaks: the authenticity of new attestations. Migration therefore has to finish before such a computer exists.

The design:

  1. Crypto agility. All verification already sits in one library (Attestations.sol). Next, move it behind a verifier contract, selected per key type and replaceable by governance, so a migration needs no redeploy of the ledger.
  2. Hybrid period. For the attestations that create value (recovery consents, destruction certificates), require both an ECDSA and an ML-DSA-44 signature (FIPS 204, final since 2024) over the same EIP-712 digest.
  3. Cost.
    • An ML-DSA-44 signature is 2,420 bytes.
    • Fireblocks reports a FIPS 204-compliant EVM verifier at about 1.23 million gas per verification. The 20 KB expanded public key is deployed once as contract code, for about 4.1 million gas [11].
    • At the OP Mainnet price above, a verification costs under one cent.
    • A draft precompile (EIP-8051, 4,500 gas) would make it negligible [10], and a permissioned chain can add one itself.
  4. Devices. Scales and lab instruments sign rarely. ML-DSA has been benchmarked on Cortex-M4 and Cortex-M0+ microcontrollers [14], so signing in the scale is expected to be feasible. We have not tested it on scale hardware.

C. Climate impact and emission-reduction estimate

Kigali Balance is an enabler. It recovers no gas and claims no credits; any reduction belongs first to whoever recovers, destroys or pays, and the project will never claim credits for its own role.

What follows propagates stated assumptions; it is not a forecast. The ranges follow from two assumed distributions and one accounting choice, and the Monte Carlo does not make them more certain. Code, inputs with sources, and a longer discussion: analysis/impact/.

C.1 How a ledger could reduce emissions

  1. More recovery (pathway 1). Recovered kilograms become verifiable. Carbon buyers, extended-producer-responsibility schemes and the reclaimed premium can then pay for recovery without paying for fakes. More payment means more recovery, and less venting at end of life.
  2. Closing the “reclaimed” exit (pathway 2). Virgin or smuggled gas can no longer be sold under the reclaimed label, its most profitable outlet.

The two pathways must not be added: they can count the same molecules twice.

C.2 Pathway 1, sized on a market like Japan's

Why Japan. We use Japan's 2024 flows only because Japan publishes an end-of-life mass balance [3]. They convert “one percentage point of recovery” into tonnes for a market of that size. This is not an estimate of impact in Japan: there, recovery is mandated and already tracked electronically, so the ledger would add almost nothing. We found no verifiable end-of-life mass balance for Türkiye or for any EU member state.

Formula. ΔE₁ = M × Δr × GWP × α × φ.

  • M = 12,066 t reaching end of life. Data.
  • GWP = 1,835 tCO₂e per tonne, for the escaped mix. Data.
  • φ, permanence. Only destroyed gas is permanently avoided. Reclaimed gas goes back into equipment, and under a binding quota it adds to supply rather than displacing virgin gas [15].
    • Headline: φ = 0.44, Japan's destroyed share of recovered gas.
    • Upper bound: φ = 1, only possible where the quota does not bind.
  • Δr, the rise in the recovery rate. Assumption: triangular 0 / 1 / 5 percentage points.
    • Under penalty-backed law, Japan's rate rose about 13 points over 12–17 years [12].
    • New Zealand's carbon-priced scheme reached 11% recovery [16].
    • A voluntary data layer should do less than either.
  • α, the share of that rise due to verifiability rather than the payment itself. Assumption: triangular 0 / 0.3 / 0.8. No study separates the two. α can be zero: Norway refunds its HFC tax on gas delivered for destruction without any shared ledger [13].

What the median means. It corresponds to an attributable rise in recovery (Δr × α) of 0.6 percentage points. One attributable point is 121 t of gas a year in a market of this size: 0.10 MtCO₂e on the headline, 0.22 on the upper bound.

For scale. TEAP estimates that 250,000–400,000 t of ODS and HFCs are decommissioned worldwide each year [16]. That makes one attributable point worth 2,500–4,000 t of gas, 21–33 times a Japan-sized market. This is a ceiling, since the figure includes ODS and foams.

C.4 How a pilot would measure the assumption that matters

Δr and α enter only as a product, so the stage-2 pilot measures Δr × α directly. It has three matched arms of scrapped units:

  • (A) payment per recovered kilogram, verified through the ledger;
  • (B) the same payment, verified on paper;
  • (C) no payment.

The outcome must be measured identically in every arm, independently of the ledger and of any paperwork, by a physical audit of a random sample of scrapped units; otherwise fraud inflates the paper arm. The same audit records destroyed versus reclaimed gas, which pins down φ.

Sample size. Assume a 43% baseline (two-sided 5%, power 80%), with clustering by technician (an illustrative design effect of 1.95). Detecting a 1-point difference then needs about 75,000 units per arm; 4 points, about 4,700. A pilot of a few thousand units can rule out the upper end but cannot measure the 0.6-point median. We say so now so that nobody reads a small pilot as proof.

C.5 What the integrity gain is, and is not

The cut in launderable volume (B.4) is not itself an emission reduction. It is what makes paying for recovery, and therefore pathway 1, safe. HFC destruction crediting is only now opening (Verra VM0016 v2.0 in December 2025, Isometric, a Taiwanese draft methodology in 2026), which is why the safeguard matters now.

E. Testing results

We have not tested with real users, and we do not claim to have. What we did instead:

  • Outside reviewers, working the way their professions do. Three reviewers with no stake in the design:
    • A security pre-audit (B.3): its findings changed the contracts.
    • A forensic review of every number. It cut our climate estimate by about three quarters (permanence; Japan only as a unit conversion). It also corrected our registry-audit headline: we had counted unassessed credits as having no identifier.
    • An editorial review for busy judges.
    We publish the corrected figures, not the earlier ones.
  • Reproduction by a reader with no context. A reader given only the repository URL and the README reproduced the results and hit 11 obstacles. All 11 were fixed. The CI rebuild repeats this on every push.
  • Evaluation on held-out data. Every AI module was scored on simulated runs it had never seen, and re-scored on new runs whenever the simulator or the model changed. The reports keep the versions that failed first.
  • Real public records. The registry audit checked our premise against public metadata. Of 291 California ARB reporting periods, 270 match the registry exactly, 21 are lower on the ARB side, and none is higher. Where a shared key exists, checking works. We found no evidence of double counting. The finding is that kilogram-level uniqueness across registries cannot be checked from public data.
  • User testing is stage 1 of the roadmap. The dashboard and provenance passport will be tested with a reclaimer, a registry analyst and a regulator, measuring whether each can answer “where did this kilogram come from?” unaided.

F. What it cannot do

Beyond the limits in the problem statement (§7, §9):

  • Collusion is bounded and made visible, not prevented. Off-ledger charging followed by a genuine recovery needs no false signature (B.4, T13).
  • Amounts are not yet confidential (B.5).
  • The claim lock addresses double issuance between registries, not host-country or Montreal Protocol accounting (A.7).
  • The AI results describe our simulator, which is calibrated to cited statistics but is not reality (A.6).
  • The public testnet deployment predates the current rules and the red-team fixes (B.3).
