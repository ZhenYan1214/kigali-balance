# Kigali Balance：主題確認與反思紀錄

這份文件記錄題目從「研究報告版本」收斂到「問題陳述版本」的過程：每一輪抓到什麼問題、改了什麼，以及還沒解決的風險。問題陳述本身在 [01_問題陳述_Problem_Statement.md](01_問題陳述_Problem_Statement.md)。

---

## 起點（v0，來自驗證報告）

> 一個從進口配額一路追到銷毀的 HFC 冷媒全生命週期帳本：鋼瓶上鏈、技師紀錄上鏈、回收與銷毀上鏈，用 AI 偵測異常，並防止銷毀碳權被重複計算。

---

## 第一輪反思：題目本身站不站得住？

### 問題 1：範圍太大，前半段在重做別人已經做好的系統
- 進口和配額這一段，歐盟 F-gas Portal 加海關單一窗口（CERTEX）已經做了，土耳其的配額系統 FARAVET 也做了。
- 技師紀錄這一段，義大利 Banca Dati、土耳其 EKOMVET、日本 RaMS 都有。
- 如果題目寫成「全生命週期追蹤」，評審第一個問題就會是「這不是已經有了嗎？」

**修正：** 把題目收斂到**會產生金錢價值的三個標籤**：「已回收」「已再生」「已銷毀」。
- 「再生」標籤值錢。歐盟禁止用高 GWP 的原生冷媒維修冷凍設備（例如 R-404A），但再生冷媒可以用到 2030 年，也不必占用逐年縮減的配額。
- 「銷毀」標籤值錢。2025 到 2026 年間，Verra、Isometric、台灣草案陸續開放冷媒銷毀碳權。
- 上游的配額系統**只當作引用的錨點，不重做**。

### 問題 2：走私的矛盾，帳本追蹤不到從沒進帳本的東西
- 原本把痛點寫成「防走私」，但走私者根本不會登記，帳本對走私貨完全看不見。這是致命漏洞，評審一定會問。

**修正：** 敘事改成兩件帳本真正做得到的事。
1. **正面證明合法來源**：合法冷媒可以出示完整的公斤來源鏈。超市、鐵路公司這類大型使用者可以要求供應商出示，沒有來源鏈的冷媒自然就被排除在外。
2. **防止洗白**：走私的原生冷媒最好賣的出路，就是貼上「再生」標籤進入合法市場。只要規定「再生產出量 ≤ 有文件的回收進料量」，就能直接堵住這個漏洞。EIA 2026 年的報告明確列出「把原生冷媒標成再生」是主要造假手法之一。

### 問題 3：主要使用者不明確
- v0 列了兩組使用者（碳權查證機構、國家臭氧單位），問題陳述會變得發散。

**修正：** 用「誰在虧錢、誰願意付錢」來排順序。
- **受害且願意付錢的**：守法的再生業者和經銷商（被便宜的非法冷媒搶走市場）、碳權註冊處與買家（怕買到假銷毀）。
- **需要證明的**：超市、鐵路這類大型使用者（EIA 揭露非法冷媒已流入這些供應鏈）。
- **次要使用者**：主管機關（臭氧單位、海關）拿到跨段落的異常訊號。
- **不當主要使用者**：技師。他們負擔最重、好處最少。美國 EPA 的鋼瓶 QR 追蹤規定，就是在業界反彈下被撤銷的。

## 第二輪反思：每個說法有沒有誇大？

| 原本的說法 | 問題 | 改成 |
|---|---|---|
| 「沒有人在跨段落對帳」 | 太絕對。日本 RaMS 的行程管理票在**一國之內**就有串起回收、再生、銷毀 | 「我們沒有找到任何**跨國境或跨碳權註冊處**對帳的系統」，同時說明日本的瓶頸是回收率卡在 43%，而不是洗白 |
| 「義大利近半市場是非法冷媒」 | 這是產業協會的說法，EIA 研究員自己也說規模很難估 | **不使用**，改用有出處的查扣量（約 250 噸增加到約 670 噸） |
| 「銷毀碳權和 Kigali 國家會計重複計算」 | 沒有任何文件化的案例 | 不當痛點，只當作系統的設計防護 |
| 「後量子簽章」 | 找不到需要它的威脅模型，評審會覺得是在堆流行詞 | 只在計畫書的威脅模型裡用一行交代「加密敏捷性」 |
| 土耳其的 HFC 削減時程 | 土耳其屬於蒙特婁議定書第 5 條還是非第 5 條國家，研究中沒有確認 | **不寫時程**，只寫有出處的事實：2024-10-15 發布的法規、FARAVET、EKOMVET、廢 F-gas 通函還在草案 |
| 「用 AI 檢查照片和檢驗報告」 | Recoolit 已經在做，不是差異化 | AI 改成綁定物理守恆和帳本的三件事（見第三輪） |

## 第三輪反思：AI 和區塊鏈是不是真的必要？

### AI：從「看照片」改成「用物理找出不合理」
1. **質量平衡異常**：再生業者的產率不合理、經銷商的銷售量超過有配額支撐的進貨量。
2. **洩漏落差**：用設備類型、年齡、充填量推估合理的補充灌注量，再和申報值比較。動機是日本的數據：業者申報洩漏 575 噸，政府盤查估計 6,283 噸，差了 10 倍以上。
3. **回收合理性**（這一輪新找到的設計）：一台設備回收出來的冷媒，**不可能多於它登記的充填量**。這條是硬性規則，交給智慧合約執行。AI 負責更細的判斷：依設備年齡和維修紀錄推估「合理的殘留量」，標記貼著上限回收、或剛登記就報廢的可疑設備。

AI 的輸出一律是「標記，交由人工複核」，不讓 AI 自動判定任何人違規。

### 區塊鏈：誠實版本
- **在單一國家內不需要**。日本 RaMS 證明中央資料庫就做得到，問題陳述裡要主動講這句話。
- **需要的場景只有三種**：跨國境（土耳其與歐盟之間）、跨碳權註冊處（Verra、Isometric、ACR、台灣，彼此互不隸屬）、互相競爭的再生業者。這三種都符合「沒有一個各方都信任的第三方」的判斷標準。
- **區塊鏈的價值**：把「守恆」從每年一次的事後稽核，變成寫入時就強制的規則；要說謊，必須讓多個彼此獨立的交易對手一起串通。
- **區塊鏈做不到的事也要寫清楚**：它看不到鋼瓶裡裝的是什麼。物理上的真實性來自秤重和實驗室檢驗，這兩件事 Isometric 協議本來就強制要求。

## 第四輪反思：評審會怎麼攻擊？

| 評審可能的質疑 | 回答 |
|---|---|
| 「這是貿易犯罪，跟氣候有什麼關係？」 | 寫出因果鏈：報廢回收是庫存冷媒逸散的最大缺口 → 要提高回收率，就得替「回收的公斤」付錢（碳權、EPR、再生溢價） → 但付錢就會引來造假 → 可驗證的公斤是付錢的前提。另外，被洗白的原生冷媒等於在配額之外多出供應，直接侵蝕削減效果 |
| 「造假的人登記一台假設備就好了？」 | 設備資料來自國家登錄系統（例如 EKOMVET 由持證技師登錄），而且有維修歷史；AI 會標記「剛登記就報廢、又貼著上限回收」的設備 |
| 「業者為什麼要加入？」 | 靠拉力而不是強制：想拿碳權、想賣再生溢價的業者才需要加入，資料也是重複使用他們已經申報的內容 |
| 「銷毀碳權不就是 HFC-23 那種漂綠嗎？」 | 承認歷史問題，再說明設計正是針對它：只有能追溯到報廢設備的公斤才能產生銷毀碳權，而且跨註冊處唯一 |
| 「面對土耳其評審講走私，不會冒犯嗎？」 | 敘事放在**保護守法的土耳其業者**：他們的合法貨物能出示來源證明，不會因為整個來源國被懷疑而被額外盤查 |

## 第五輪反思：會不會撞題？

- 2026-10-14 實際搜尋 Devpost 的 27 組關鍵字、ETHGlobal 的 16 組關鍵字：沒有任何冷媒追蹤、公斤對帳或銷毀碳權的作品。最接近的是 Devpost 上一個 AI 冷凍設備預測維護專案（RefriSafe Guard），所以「洩漏預測」不能當賣點。
- 已知前例：紐西蘭 CCCANZ 2023 年的區塊鏈冷媒計畫（沒有公開細節）、Recoolit（印尼，冷媒回收與銷毀碳權的營運商）、日本 RaMS。所以不能說「第一個區塊鏈冷媒追蹤」，差異化要放在「**跨組織的公斤守恆＋跨註冊處唯一性**」。

## 收斂後的主題（v1，用於問題陳述）

> **Kigali Balance：讓「已回收、已再生、已銷毀」的每一公斤 HFC 冷媒，都能在跨國境、跨碳權註冊處的情況下對得起帳。**
>
> 核心規則只有一條：**每一公斤被宣稱為「再生」或「銷毀」的冷媒，都必須追溯到從一台真實設備回收出來的一公斤。**

賽道：主賽道三（永續供應鏈），兼賽道一（碳市場與排放透明）。

## 第六輪反思：問題陳述初稿本身的檢查

寫完初稿後逐段重讀，又改了這些地方：

| 發現的問題 | 修正 |
|---|---|
| 沒有正面回答「走私者根本不會登記，帳本怎麼抓？」 | 第 7 節新增「帳本的兩個限制」：看不到鋼瓶內容、抓不到沒進帳本的冷媒。並說明它改為讓合法冷媒**可被證明**，同時堵住非法冷媒以「再生」名義洗白這條最賺錢的出路 |
| 沒交代業者為什麼要加入 | 第 8 節新增「不需要新法規也能推廣」：業者為了碳權資格或再生溢價而加入；並引用美國 QR 規定的失敗作為反面教材 |
| 「日本有全世界最嚴格的法規」是主觀說法 | 改成「最完整的生命週期法規之一」 |
| 「美國 QR 規定在業界反彈下撤回」不精確 | 改成「先被法院撤銷，之後在業界反彈下正式撤回」 |
| 英文版排成 PDF 有 3 頁，超過限制 | 第 5、6、9 節改成緊湊格式（內容不刪），實測為 A4 2 頁；並加上分頁控制，避免標題落在頁尾、內容跑到下一頁 |
| 「再生冷媒不受配額限制」原本只有推論 | 補查德國聯邦環境署的資料確認，並補上「境外進口的再生冷媒仍受配額」這個細節，反而讓「境內再生」標籤的價值更清楚 |

## 第七輪反思：寫計畫書時發現的設計問題

| 發現的問題 | 修正 |
|---|---|
| 防重複核發原本用「指紋比對」：各註冊處比對由事件資料算出的雜湊。但造假者只要改動檢驗報告的任一欄位，指紋就會不同，比對失效 | 改成**認領鎖**：銷毀事件本身是帳本上的一筆狀態，只能由持有該批次的銷毀廠產生，而且只能被一個註冊處認領一次。問題陳述第 6 節同步改寫，PDF 重新產生後仍是 2 頁 |
| 小型設備（家用冷氣等）在 EKOMVET 沒有登錄紀錄（門檻 5 tCO₂e），但日本家用冷氣報廢約占 HFC 排放的 16%；照原設計，這些回收全會變成「來源不明」 | 設備分兩個信任等級：A 級來自國家登錄系統；B 級在報廢時以銘牌照片加型號查核登錄，並限制每位技師每月的回收總量。AI 對 B 級做更嚴格的檢查，註冊處也可自行決定是否接受 |
| 「技師不增加工作」說得太滿：改用簽章電子秤其實是新設備 | 改成「不需要額外填寫文件」，並說明電子秤的成本由想取得碳權或再生溢價的一方負擔 |
| 時程表的星期全部錯一天（2026-10-15 是星期四） | 已用系統日期核對並修正 |
| 「Besu 私有交易功能已不再推薦」是憑印象寫的，沒有查證 | 改成中性寫法「不依賴私有交易功能」，理由改為降低複雜度 |

## 第八輪反思：寫智慧合約與測試時發現的問題

| 發現的問題 | 嚴重度 | 修正 |
|---|---|---|
| **灌注後立即回收的洗白漏洞**：把原生冷媒灌進已登錄設備、隔天回收，就能從「原生」變成「回收」類別，繞過整個設計 | 高 | 新增駐留規則與 C 級：安裝或最近一次帳本灌注後未滿 180 天就回收的冷媒，自動標為 C 級，不能再生、不能申請碳權。新增 7 個專門測試，模糊測試也加入不變量檢查 |
| 模糊測試「全部通過」，但再生和銷毀其實幾乎沒有成功執行過，等於沒驗證到 | 中 | 加入有方向性的流程與「誠實操作」，並把每一輪的結果寫入 CSV 統計。256 輪中：合法再生 631 次、違規再生被擋 1,281 次、碳權認領成功 568 次、重複或不合格認領被擋 1,470 次，7 條不變量全部成立 |
| 跨鏈簽章測試失敗 | 低（測試本身的錯） | 查證後發現合約正確，是 via_ir 編譯會重排測試中的 `block.chainid` 讀取；改成直接用另一條鏈的 EIP-712 網域算摘要 |
| 不變量 4 原本拿「再生批次目前重量」檢查，批次拆分後重量變小，檢查太寬鬆 | 中 | 改為記錄「產出當下的重量」再檢查 |
| `setLedger`、治理地址沒有零地址檢查 | 低 | 已補上 |
| 計畫書寫「Ed25519 簽章」，但 EVM 無法直接驗證 Ed25519 | 低 | 改為 EIP-712＋secp256k1 ECDSA，可在鏈上直接驗證；驗章集中在一個函式庫，保留加密敏捷性 |

**結果**：6 個合約、107 個測試全部通過；原始合約的行覆蓋率 84–100%；lint 警告逐條分類，只有零地址檢查是真問題，已修正。

## 第九輪反思：寫模擬資料產生器時發現的問題

| 發現的問題 | 嚴重度 | 修正 |
|---|---|---|
| **C 級規則誤傷誠實回收**：設備常在報廢前幾週補充冷媒，原規則會讓整台設備的冷媒都變成 C 級 | 高 | 合約改為只隔離「近 180 天內經帳本灌注的那幾公克」，其餘維持原等級。模擬結果：誠實報廢回收中 17% 的設備有部分被隔離，被隔離的質量占 6.8%（仍可銷毀或灌回，只是不能申請碳權）；9 次洗白嘗試全部被完整隔離 |
| **答案洩漏給 AI**：`invoices.csv` 有一欄直接標示走私發票；造假設備編號是 `eq-phantom-…`；連編號範圍都和真設備不同 | 高 | 發票只保留一般稅務欄位，AI 必須自己對帳；所有設備改用同一空間的隨機序號；新增自動測試，檢查觀測資料中沒有任何標籤字樣 |
| R-410A 配額比最小下單量還小，導致 12.9 萬次假的「超過配額」拒絕，補充需求也悄悄沒被滿足 | 高 | 下單量依各冷媒市場規模縮放、進口商不會超額請求；新增「未滿足補充需求」指標（現為 0） |
| 模擬事件時間會倒退（例如第 2 天之後又出現第 1 天的事件），區塊鏈上不可能發生 | 中 | 帳本鏡像加入單調時鐘（相鄰事件至少間隔 60 秒）；配額改在每年年初於迴圈內發放 |
| 再生產率的誠實與造假區間完全不重疊，AI 用單一門檻就能抓到，沒有意義 | 中 | 改為重疊區間（誠實 85–95%、造假 93–98%），AI 必須綜合多個訊號 |
| 模擬器的規則鏡像可能和真正的合約不一致 | 高 | 新增差異測試：把 9,469 筆事件全部重播到本機鏈上的真合約，接受／拒絕結果、拒絕原因、批次編號、各冷媒總量全部一致 |
| 重播工具在 Windows 上曾殘留鏈節點、可能和其他工作階段的本機鏈衝突 | 低 | 改用隨機連接埠、只依自己啟動的程序編號關閉、啟動時檢查鏈是否全新、送交易失敗時重新同步 nonce |
| 單一亂數種子的回收率 0.49，高於目標 0.43 | 低（查證後非問題） | 跑 20 個種子，平均 0.405（範圍 0.27–0.60），比目標低 0.025，在測試容許的 ±0.05 內；單一種子的偏差來自少數大型設備。（原紀錄寫平均 0.436，2026-10-15 在新電腦重算後更正） |

**結果**：模擬器 15 個自動測試全部通過；每次執行都自動檢查物理質量平衡、帳本恆等式、每筆事件的規則符合性；校準到日本 2024 年 43% 回收率。

## 還沒解決的風險（寫計畫書前要處理或接受）
